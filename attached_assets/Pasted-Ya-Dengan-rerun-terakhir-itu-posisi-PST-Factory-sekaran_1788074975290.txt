## Sekarang bottleneck memang Factory Learning

Dan saya setuju dengan keputusan sebelumnya: **jangan menyentuh #43 selama masih `PENDING / BLOCKED_BY_CONCURRENCY`.**

Karena Factory Learning adalah fase baru, bukan sekadar fitur tambahan.

Ia harus menjawab pertanyaan:

> **Bagaimana pengalaman menjalankan PST digunakan untuk memperbaiki konfigurasi Factory tanpa mengubah release customer yang sedang berjalan?**

Target arsitekturnya nanti kira-kira:

```text
             CUSTOMER JOURNEY
                    ↓
              Runtime Events
                    ↓
             Outcome / Evidence
                    ↓
              Learning Signal
                    ↓
          ┌─────────┴─────────┐
          ↓                   ↓
      Pattern             Recipe
          ↓                   ↓
       Knowledge / Configuration
                    ↓
             QA / Human Gate
                    ↓
              New Blueprint
                    ↓
             New Snapshot
                    ↓
          Same Validator
                    ↓
           Same Compiler
                    ↓
            Same Runtime
                    ↓
          NEW RELEASE
```

Perhatikan satu hal penting:

**Learning tidak menyentuh release lama.**

Misalnya customer sedang menggunakan:

```text
Release v1.0
```

Factory Learning menemukan bahwa sebuah pertanyaan kurang efektif.

Maka **bukan**:

```text
v1.0 → diubah
```

melainkan:

```text
v1.0  ← tetap immutable
 │
 └── evidence
       ↓
   learning
       ↓
   configuration
       ↓
   v1.1 candidate
       ↓
   validate
       ↓
   compile
       ↓
   QA
       ↓
   publish v1.1
```

Ini akan menjadi bukti bahwa PST Factory bukan hanya **manufacturing engine**, tetapi mulai menjadi **learning manufacturing system**.

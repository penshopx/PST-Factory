## Mengapa ini sangat penting?

Compiler nantinya harus menjadi:

```text
                BLUEPRINT
                    │
                    ▼
              PST COMPILER
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
 Input Schema    Logic        Output Schema
       │            │            │
       └────────────┼────────────┘
                    ▼
             EXECUTABLE PST
                    │
                    ▼
           CUSTOMER RUNTIME
```

Bukan:

```text
Blueprint
   ↓
generate custom code
   ↓
PST #001 code
PST #002 code
PST #003 code
```

Kalau Compiler menghasilkan custom code per produk, kita **belum memiliki Factory**. Kita hanya punya code generator.

# Acceptance Compiler yang saya sarankan

Sebelum Replit diberi izin coding Compiler, kontraknya harus mampu menjelaskan bagaimana minimal tiga PST diterjemahkan:

### Cashflow Health Check

```text
Input
→ Questions
→ Financial scoring
→ Diagnosis
→ Recommendation
→ Action plan
```

### Decision Readiness

```text
Options
→ Criteria
→ Weighting
→ Score
→ Comparison
→ Recommendation
```

### Document Compliance

```text
Document
→ Extraction
→ Checklist
→ Validation
→ Compliance score
→ Gap report
```

Ketiganya harus menggunakan **Compiler yang sama**.

Yang berbeda hanya:

```text
Schema
Pattern
Recipe
Rules
Knowledge
Configuration
```

## Dan saya ingin satu prinsip ditambahkan

Compiler harus memiliki konsep **validation sebelum compilation**:

```text
Blueprint
   ↓
Validate
   │
   ├── ❌ invalid → STOP
   │
   └── ✅ valid
          ↓
       Compile
          ↓
   Executable PST
```

Jadi jangan sampai Blueprint yang belum lengkap menghasilkan runtime setengah jadi.

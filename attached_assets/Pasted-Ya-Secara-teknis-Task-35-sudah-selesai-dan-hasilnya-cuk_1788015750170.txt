```text
       ↓
   COMPILER
       ↓
Executable PST Definition
       ↓

```

## Apa itu Manufacturing IR?

Anggap saja IR sebagai **bahasa mesin PST**.

Misalnya Cashflow Health Check memiliki:

```text
Input:
- omzet
- piutang
- hutang
- saldo kas

Process:
- calculate ratios
- evaluate thresholds
- classify health

Output:
- health score
- diagnosis
- recommendations
- action plan
```

Sedangkan Decision Readiness:

```text
Input:
- decision context
- alternatives
- criteria
- constraints

Process:
- weighted scoring
- comparison
- risk evaluation

Output:
- readiness score
- preferred option
- risk notes
- action plan
```

Document Compliance:

```text
Input:
- document
- required criteria

Process:
- requirement checking
- evidence evaluation
- gap analysis

Output:
- compliance status
- missing items
- recommendations
```

**Ketiganya berbeda.**

Tetapi bahasa mesinnya harus sama:

```text
INPUT
→ COLLECT
→ VALIDATE
→ EVALUATE
→ SCORE
→ ANALYZE
→ GENERATE OUTPUT
→ ACTION
→ COMPLETE
```

Konfigurasinya yang berbeda.

# Saya juga menyarankan satu perubahan cara berpikir

Jangan menganggap:

> **Compiler = generator halaman**

Compiler harus menjadi:

> **transformer dari deklarasi PST menjadi executable definition.**

Sehingga:

```text
Snapshot
   ↓
Normalize
   ↓
Validate
   ↓
Manufacturing IR
   ↓
Compile
   ↓
Executable PST Definition
```

Contohnya secara konseptual:

```text
Executable PST Definition

{
  schemaVersion,
  pstIdentity,

  inputs: [...],

  journey: [...],

  operations: [...],

  rules: [...],

  scoring: {...},

  outputs: [...],

  actions: [...],

  completion: {...}
}
```

**Runtime tidak perlu tahu ini Cashflow atau Decision.**

Runtime cukup berkata:

> "Saya diberi Executable PST Definition. Saya jalankan."

Itulah titik ketika PST Factory benar-benar berubah dari **builder** menjadi **manufacturing engine**.
